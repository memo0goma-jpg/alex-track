# ALEX TRACK — موقع سوق المعدات وتطبيق Android

مشروع React + TypeScript + Vite مع Capacitor لتشغيل واجهة الويب وتجهيز تطبيق Android. تم الحفاظ على اسم ALEX TRACK والهوية والألوان والأقسام والواجهات الأصلية، وإضافة طبقة تكامل فعلية مع Supabase عند ضبط متغيرات البيئة.

## ما يحتويه المشروع

- واجهة عربية/إنجليزية، وعرض الأسعار بالجنيه المصري أو الدولار.
- أقسام المعدات الثقيلة والزراعية وقطع الغيار والملحقات، مع البحث والتصفية والتفاصيل والمقارنة والمفضلة.
- حسابات مشترٍ وبائع ومدير، وتسجيل/دخول/استعادة كلمة المرور عبر Supabase Auth.
- قراءة المعدات والتصنيفات والبانرات والتقييمات من Supabase.
- حفظ إعلانات المعدات وصورها، والاستفسارات والردود، والتقييمات، والبلاغات، وتعديلات البانرات، ومراجعة المستخدمين.
- PostgreSQL schema وفهارس وسياسات RLS وتخزين صور في Storage.
- وضع تجريبي محلي عند عدم إعداد Supabase؛ لا يُستخدم كحساب حقيقي ولا يشارك البيانات بين الأجهزة.

## تشغيل الموقع

1. ثبّت Node.js LTS.
2. من مجلد المشروع نفّذ `npm install`.
3. شغّل `npm run dev`.
4. افتح رابط Vite الظاهر في الطرفية.

## ربط Supabase

1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح `supabase/schema.sql` وانسخ محتواه كاملًا إلى **SQL Editor** في لوحة Supabase، ثم اضغط Run.
3. من Project Settings → API انسخ **Project URL** و **anon/public key** فقط.
4. انسخ `.env.example` إلى ملف اسمه `.env` داخل جذر المشروع، ثم أدخل القيم:

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
   ```

5. أوقف Vite وأعد تشغيل `npm run dev` بعد إضافة `.env`.
6. من Authentication → URL Configuration اضبط Site URL على عنوان الموقع الفعلي، وأضف عناوين التطوير/الإنتاج إلى Redirect URLs عند الحاجة.
7. سجّل حسابًا من شاشة التسجيل. اختيار بائع ينشئ دور seller، وتظل إعلاناته قيد مراجعة الإدارة حتى اعتمادها.
8. لترقية حساب الإدارة الأول: افتح Authentication → Users، انسخ UUID الخاص بالحساب، ثم نفّذ في SQL Editor:

   ```sql
   update public.profiles
   set role = 'admin'
   where id = 'ضع-UUID-حساب-المدير-هنا';
   ```

   لا تضع هذا الأمر في كود الواجهة، ولا تسمح للمستخدم بتحديد دور admin من شاشة التسجيل.

## الأمان والمفاتيح

- لا تضع `service_role` أو مفاتيح سرية في `.env` المرسل للمتصفح أو في Git.
- المتغيران `VITE_*` متاحان داخل تطبيق الويب؛ استخدم مفتاح anon/public فقط مع سياسات RLS.
- حساب المدير يُرقّى يدويًا من لوحة Supabase. سياسات قاعدة البيانات تمنع المستخدم العادي من تعديل دوره أو توثيقه أو إيقاف حسابات الآخرين.
- إنشاء إعلان جديد من حساب بائع يبدأ بحالة `pending`، ولا يظهر للعامة قبل اعتماد الإدارة.
- الصور تُرفع إلى bucket باسم `equipment-images`، وتُحفظ داخل مجلد يحمل UUID البائع.
- لا يتم استيراد حسابات البائعين/المشترين التجريبية كحسابات حقيقية. البيانات التجريبية تبقى في الوضع المحلي فقط.

تفاصيل الإعداد والاختبار في `supabase/SETUP_AR.md`.

## تجهيز Android

بعد تثبيت Android Studio وAndroid SDK:

```bash
npm run android:add   # مرة واحدة فقط لإنشاء مشروع Android
npm run android:sync  # بناء الويب ومزامنته مع Android
npm run android:open  # فتح المشروع في Android Studio
```

لا يوجد APK جاهز ضمن هذه الحزمة؛ يجب إنشاء مجلد Android ثم بناء التطبيق من Android Studio بعد ضبط Supabase.

## حدود ما تم التحقق منه

يمكن تجهيز ملفات المشروع محليًا، لكن لا يمكن اختبار تسجيل الدخول أو القراءة والكتابة السحابية دون عنوان مشروع Supabase ومفتاحه، ولا يمكن التحقق من سياسات RLS على مشروع خارجي قبل تشغيل `schema.sql` فيه. لا يتم نشر الموقع أو إنشاء حسابات خارجية تلقائيًا.
